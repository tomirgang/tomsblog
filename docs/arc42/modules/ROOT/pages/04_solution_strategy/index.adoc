= 4. Lösungsstrategie
:sectnums:

== Architekturansatz

[cols="1,2"]
|===
| Entscheidung | Begründung

| Hexagonale Architektur | Framework-unabhängige Domain, austauschbare Adapter
| Microservices | Unabhängige Deployments, Technologie-Heterogenität (REST + GraphQL)
| Event-Driven (Kafka) | Lose Kopplung, Replay-Fähigkeit, Audit-Trail
| Multi-Tenant | Mandantenfähigkeit von Anfang an im Design
|===

== Qualitätsstrategien

* *Testbarkeit*: Domain ohne Framework-Abhängigkeiten → Pure Unit Tests
* *Nachvollziehbarkeit*: Audit-Felder in allen Entities, Requirement Tracing
* *Beobachtbarkeit*: Prometheus + Grafana + Loki + Tempo von Anfang an
* *Inkrementell*: Meilenstein-basierter Ausbau (Text-Blog → Kommentare → SPA → Podcast → Video)
