=== Domain Layer (domain/)

Reine Java-Klassen ohne Framework-Abhaengigkeiten. Die gemeinsamen Domain Primitives (EntityId, TenantId, AuthorId, AggregateRoot, DomainEvent, Auditable) werden über das Shared Kernel (SWA-002) als Framework-freie Library bereitgestellt.

[cols="1,1,2"]
|===
| Baustein | Typ | Beschreibung

| `Post` | Aggregate Root | Titel, Slug, Content, ContentType (HTML/MARKDOWN), Status, Locale, AuthorId (Referenz), TagIds, Sources, Attachments. Registriert Domain Events.
| `ContentType` | Enum | HTML, MARKDOWN. Steuert die Rendering-Logik fuer die Anzeige (SWR-035, SWA-027).
| `Translation` | Aggregate Root | Uebersetzung eines Posts mit eigenem Lifecycle (DRAFT/REVIEW_PENDING/APPROVED/REJECTED).
| `Tag` | Entity | TagId, TenantId, name, slug. Tenant-scoped mit eigener Identitaet.
| `PostId`, `TagId`, `TranslationId`, `AttachmentId` | Value Objects | Typsichere IDs (Records)
| `Slug`, `PostLocale` | Value Objects | Validierung im Konstruktor
| `Source` | Value Object | Quellenreferenz: URL + Titel
| `Attachment` | Value Object | AttachmentId, filename, contentType, size, show, storageKey. show=true fuer angezeigte, show=false fuer eingebettete Inhalte.
| `PostStatus` | Enum | DRAFT, PUBLISHED, ARCHIVED
| `TranslationStatus` | Enum | DRAFT, REVIEW_PENDING, APPROVED, REJECTED
| `TranslationSource` | Enum | MANUAL, AI_GENERATED
| `PostCreatedEvent`, `PostPublishedEvent`, `PostUpdatedEvent` | Domain Events | Post-Lifecycle-Events
| `TranslationCreatedEvent`, `TranslationApprovedEvent` | Domain Events | Translation-Lifecycle-Events
|===

NOTE: `AuthorId` liegt im `shared-kernel` (SWA-002). Der blog-content Service haelt keine Author-Stammdaten vor (werden vom Auth-Service in Phase 3 bereitgestellt).

=== Datenbank-Migrationen (Flyway)

Die Datenbank-Schema-Verwaltung erfolgt über Flyway (SWA-013). Alle Migrationen liegen unter `src/main/resources/db/migration/` und werden beim Service-Start automatisch ausgefuehrt. Hibernate validiert das Schema gegen die Entity-Klassen (`ddl-auto: validate`).

[cols="1,2"]
|===
| Migration | Beschreibung

| `V1__create_posts_schema.sql` | posts, post_tags, post_sources, post_attachments
| `V2__create_tags_schema.sql` | tags mit Unique-Index auf (tenant_id, name) und (tenant_id, slug)
| `V3__create_translations_schema.sql` | translations mit FK auf posts, Unique auf (post_id, locale)
| `V4__add_content_type_to_posts.sql` | content_type VARCHAR(20) NOT NULL DEFAULT 'HTML' (SWR-035, SWA-027)
| `V5__add_fulltext_search_index.sql` | GIN-Index fuer Volltextsuche ueber title und content mit tsvector (SWR-038)
| `V6__add_series_navigation.sql` | Optionale Serien-Navigationsfelder series_previous_post_id und series_next_post_id (SWR-040)
| `V7__add_featured_fields.sql` | Optionale Featured-Felder featured_from und featured_until (SWR-041)
| `V8__create_audit_log.sql` | Audit-Log-Tabelle mit Indizes auf tenant_id und timestamp (SWR-056, SWA-031)
|===

NOTE: Weitere Services werden analog strukturiert. Details werden ergänzt, sobald sie implementiert sind.

== Ebene 2: User Management Service

Der User Management Service verwaltet plattformspezifische Benutzerprofile, Rollen und Tenant-Zuordnungen (SWR-043, SWA-029). Er agiert als Ergänzung zum externen OIDC Provider Authentik (ADR-0027, SWR-016). Authentik übernimmt Authentifizierung (Login, MFA, Passwort-Policies), während der User Management Service die Autorisierungsdaten (Rollen, Tenant-Mitgliedschaften) intern verwaltet.

=== Domain Layer (domain/)

[cols="1,1,2"]
|===
| Baustein | Typ | Beschreibung

| `UserProfile` | Aggregate Root | OidcSubject (eindeutige OIDC-Kennung), Username, PasswordHash, AuthSource, E-Mail, DisplayName, ApprovalStatus (PENDING/APPROVED/REJECTED), Rollen, TenantMemberships. Synchronisiert sich aus OIDC-Claims oder internem Login.
| `TenantSettings` | Entity | TenantId, LoginMode, autoApproveOidc, autoApproveEmailDomains. Konfiguriert Login-Verhalten und Auto-Approval pro Tenant (SWR-044, SWR-045).
| `Role` | Enum | SUPERADMIN, ADMIN, AUTHOR, REVIEWER, READER (SWR-007). SUPERADMIN wird ueber Infrastruktur-Konfiguration angelegt.
| `AuthSource` | Enum | INTERNAL, OIDC. Gibt an, ob der Benutzer ueber internes Konto oder OIDC authentifiziert wird.
| `ApprovalStatus` | Enum | PENDING, APPROVED, REJECTED. Status der Benutzerfreigabe (STK028).
| `LoginMode` | Enum | INTERNAL, OIDC, BOTH. Konfigurierbare Login-Methode pro Tenant (SWR-044).
| `TenantMembership` | Value Object | TenantId + Role. Ein Benutzer kann in verschiedenen Tenants unterschiedliche Rollen haben.
| `UserProfileId` | Value Object | Typsichere ID (Record)
|===
