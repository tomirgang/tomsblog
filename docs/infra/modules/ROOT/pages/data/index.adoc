= Datenhaltung
:sectnums:

== Überblick

Die Plattform folgt dem Database-per-Service-Pattern (ADR-0019). Aktuell wird PostgreSQL als primäre Datenbank eingesetzt, verwaltet durch den CloudNativePG Operator (INF-005). Für das Session Management wird Redis als externer Session-Store betrieben (ADR-0030, INF-014).

=== Strategie

[cols="1,2"]
|===
| Prinzip | Umsetzung

| Database per Service | Jeder Service bekommt eigene DB-Instanz
| Operator-managed | CloudNativePG verwaltet Lifecycle, Failover, Backup
| Session-Store | Redis für horizontale Skalierung (Spring Session)
| GitOps | Cluster-Definition als YAML in `infra/k8s/postgres/` und `infra/k8s/redis/`
| Verschlüsselung | mTLS zwischen App und DB/Redis (Linkerd)
|===
