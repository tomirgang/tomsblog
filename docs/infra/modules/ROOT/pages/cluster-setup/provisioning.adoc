= Provisionierung
:sectnums:

== Repository

Die Cluster-Provisionierung erfolgt im Repository `kubernetes-playground/k3s/` mit dem CLI-Tool https://github.com/vitobotta/hetzner-k3s[hetzner-k3s] (INF-001, SWA-017). Dieses Repository enthält:

* `cluster.yaml` -- Deklarative Cluster-Konfiguration (Nodes, Netzwerk, k3s-Version)
* `README.md` -- Anleitung zur Installation und Verwaltung

=== Provisionierungs-Workflow

Der folgende Ablauf beschreibt die initiale Cluster-Erstellung und Updates:

[mermaid]
----
sequenceDiagram
    participant Dev as Entwickler
    participant CLI as hetzner-k3s CLI
    participant HC as Hetzner Cloud API
    participant K8s as K8s Cluster

    Dev->>CLI: hetzner-k3s create --config cluster.yaml
    CLI->>HC: Erstelle Nodes, Netzwerk
    HC-->>CLI: Ressourcen erstellt
    CLI->>K8s: k3s Bootstrap (via SSH)
    K8s-->>CLI: Cluster bereit (kubeconfig)
    Note over Dev: Flux Bootstrap manuell
    Note over K8s: Flux übernimmt App-Deployment
----

=== Trennung der Verantwortlichkeiten

[cols="1,2,1"]
|===
| Schicht | Verantwortung | Repository

| Plattform | Nodes, Netzwerk, k3s, Hetzner CSI/CCM | kubernetes-playground/k3s/
| Applikation | DB-Instanzen, Services, Ingress, Policies | tomsblog/infra/k8s/
|===

Diese Trennung stellt sicher, dass Plattform-Änderungen (z.B. Node-Upgrade) unabhängig von Applikations-Deployments durchgeführt werden können.

== Node-Konfiguration

k3s wird in Version v1.33.1+k3s1 installiert. Workloads werden nicht auf dem Controller gescheduled (`schedule_workloads_on_masters: false`).

[cols="1,1,1,1"]
|===
| Rolle | Typ | vCPU | RAM

| Controller | CPX22 | 2 | 4 GB
| Worker 1 | CPX22 | 2 | 4 GB
| Worker 2 | CPX22 | 2 | 4 GB
|===

== Cluster-Verwaltung

Das `hetzner-k3s` CLI bietet idempotente Befehle für die Cluster-Verwaltung:

* **Erstellen/Skalieren**: `hetzner-k3s create --config cluster.yaml` (idempotent, kann beliebig oft ausgeführt werden)
* **Upgrades**: k3s-Version in `cluster.yaml` ändern, dann `hetzner-k3s upgrade --config cluster.yaml`
* **Löschen**: `hetzner-k3s delete --config cluster.yaml`

== Basis-Operatoren

Nach der Cluster-Erstellung werden die folgenden Operatoren manuell oder via Flux installiert:

* **CloudNativePG** -- PostgreSQL-Operator (CRDs + Controller)
* **Linkerd** -- Service Mesh (CRDs + Control Plane)
* **Reflector** -- Cross-Namespace Secret-Synchronisation

Die applikationsspezifischen Custom Resources (z.B. PostgreSQL-Cluster-Definition, ClusterIssuer) liegen im App-Repository unter `infra/k8s/`.
