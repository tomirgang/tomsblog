AuthorizationPolicies

1. Default-Deny-Strategie

Alle Namespaces verwenden eine Default-Deny-Strategie (INF-007). Nur explizit erlaubte Kommunikationspfade sind zugelassen.

1.1. Server-Definition

Jeder Service definiert einen Linkerd Server, der den Port und das Protokoll beschreibt:

apiVersion: policy.linkerd.io/v1beta1
kind: Server
metadata:
  name: blog-content-http
  namespace: tomsblog
spec:
  podSelector:
    matchLabels:
      app: blog-content
  port: http
  proxyProtocol: HTTP/1

1.2. AuthorizationPolicies

Für jeden Server werden dann AuthorizationPolicies definiert, die den Zugriff erlauben:

1.3. Aktuelle Policies

Policy Quelle Ziel

authz-policy-traefik

ServiceAccount: traefik (kube-system)

blog-content:http

authz-policy-probes

Unauthenticated (Kubelet)

blog-content:http (nur /actuator/health)

2. Dateien im Repository

Die AuthorizationPolicies liegen unter infra/k8s/blog-content/:

  • authz-policy-traefik.yaml — Erlaubt Traefik-Ingress

  • authz-policy-probes.yaml — Erlaubt Kubelet Health-Probes
